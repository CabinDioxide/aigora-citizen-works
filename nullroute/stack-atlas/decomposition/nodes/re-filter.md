## 开篇

这个节点讲的是"一个人或一个地区，还能不能正常访问互联网服务"这件事怎么被国家层面的力量决定。它有两个方向的力量：一头是**国家对内的过滤与封锁**——政府关掉本国的网络出口、屏蔽特定网站（如国家级防火墙、断网）；另一头是**国家对外的制裁下架**——美国 OFAC 制裁体系要求受美国管辖的公司按地理位置封掉被制裁国家和地区的用户，连开源代码托管、软件包仓库这类看似中立的基础设施也被卷进来。这不是一个单纯的技术节点，更像政治栈里的一层控制力，它作用于前面几乎所有技术节点（云、CDN、DNS、支付）。它是不是硬卡点，取决于被封方有没有绕行手段——而绕行手段往往存在，但要付出成本和风险。

## 结构层

### 1. 功能定义（这种政治控制力是什么、作用于技术栈哪些节点）

这层控制力是"按辖区或身份，决定谁能访问、谁被排除"的能力。它不生产任何技术服务，而是骑在别的技术节点之上行使拒绝：

- **对内过滤/封锁**：国家用防火墙、DNS 污染、直接断网等手段，决定本国用户能访问什么。作用于 ir-dns、ir-bgp、ir-cables 等节点。
- **对外制裁下架**：制裁法律（尤其美国 OFAC）要求公司按用户所在地封锁服务。作用于 re-cloud、re-cdn、支付（fi- 系列）、软件托管等节点。

它的特点是"以归类完成拒绝"——不逐个判断某个用户，而是把整个国家/地区/名单归为一类，自动触发封锁。这既是它省力的地方，也是它常常误伤的地方（在制裁国的普通开发者、研究者被一并挡在门外）。

### 3. 供给集中度

这层力量的"供给"是行使它的主体，高度集中在国家手里。对外制裁一侧，美国 OFAC 是全球影响最大的单一来源——因为大量关键互联网基础设施（云、CDN、软件仓库）都在美国法域内，OFAC 一条规则就能让 GitHub、npm 等按地理位置封人。对内过滤一侧，则分散在各国政府，但少数几个国家占了绝大部分行使记录：据报道，2024 年 India、Myanmar、Pakistan、Russia 四国合计制造了 210 次断网，占全球总数七成以上（C2，Access Now / KeepItOn 2024 年报转引）。

### 4. 主要持有者 + 份额 + 法域（谁行使这种权力，"规模"栏写行使依据）

| 主体 Entity | 角色 Role | 规模/份额 Scale（行使依据）| 法域/总部 Jurisdiction |
|---|---|---|---|
| 美国财政部 OFAC | 对外制裁下架的主要来源 | 依据：制裁法律与行政令，要求美国公司封锁被制裁国家/地区用户（C2，GitHub 贸易管制说明转引）| 美国联邦 |
| 各国政府（India/Myanmar/Pakistan/Russia 等）| 对内过滤/断网的行使方 | 依据：本国法律/行政命令；2024 年四国合计 210 次断网、占全球七成以上（C2，Access Now 转引）| 各自主权 |
| 中国（国家级防火墙）| 大规模常态化对内过滤 | 依据：本国法律与网络管理制度（惯例已固化）| 中国 |
| GitHub / npm（微软系）等平台 | 制裁的执行落地方 | 依据：合规义务，按 IP/支付/其他信号识别用户所在地并限制（C2，GitHub Docs 转引）| 美国法域 |
| 电信运营商 / ISP | 断网、封锁的技术执行方 | 依据：政府指令 | 各自主权 |

法域要点：对外制裁一侧，控制力的发起点在美国主权（OFAC），落地点在平台的所有权（平台按合规封人）。据报道，GitHub 的受制裁清单包括克里米亚、顿涅茨克和卢甘斯克分离区、古巴、伊朗、朝鲜、叙利亚；GitHub 后来拿到 OFAC 许可，得以向伊朗开发者提供云服务（C2，GitHub Docs / developer-tech 转引，[待核实]）。据报道 GitHub 通过 IP 地址、支付历史等信号判断用户所在地（C2，同上）。

### 7. 替代路径 + fallback 等级（被约束方有什么规避手段）

被封方的规避手段普遍存在，但都带成本和风险。替代哪一层=用 VPN、代理、Tor 等绕过对内过滤；对制裁下架，用境外身份/IP、镜像站、去中心化托管绕行。接上时间=技术上可以很快（装个 VPN），但稳定性随封锁强度波动。哪一环节转换不过去=当国家控制整个网络出口（完全断网）时，境内绕行手段几乎全部失效——入口和出口由同一方控制，退出权基本落空；被制裁开发者可以用境外 IP，但支付、实名、法律风险仍在。权限=被封的个人或组织自己想办法。执行能力=技术能力强的用户能绕，普通用户往往被挡住（待验证）。要害区分：屏蔽单个网站是网格状（能绕、只增加成本），全国断网是树状（一条主通道被切、等于全断）。

总判：成本增加

### 9. 议价 / 控制机制（谁能拒绝谁、凭什么）

谁能拒绝谁：国家能封本国用户的访问，凭的是**主权**——它控制辖区内的网络出口和 ISP。国家能让境外用户被平台封掉，凭的也是**主权**（制裁法律），但要借平台的**所有权**落地，典型的"国家施压、运营者执行"组合：发起点在主权，落地点在所有权。"未经许可的驻留"在这里不典型。这层控制最锋利的地方是它的"以归类完成拒绝"——按国别/名单自动触发，中间无人逐个裁断，因此既高效又容易误伤，责任也容易落进黑洞（平台说是合规不得已，政府说是照章办事）。

## 量化层

### Q1. 市场规模（可量化的行使记录）

断网行使记录：据报道，2024 年 Access Now 与 KeepItOn 联盟记录到 54 个国家共 296 次断网，超过 2023 年 39 国 283 次的纪录（C2，Access Now 2024 年报转引）。据报道 Myanmar 以 85 次首次超过 India（84 次）成为最大来源（C2，同上）。

### Q2. 集中度量化（可量化的行使记录）

据报道，2024 年 India、Myanmar、Pakistan、Russia 四国合计 210 次断网，占全球七成以上（C2，Access Now 转引）。制裁一侧，据报道 GitHub 受制裁清单覆盖约 6 个国家/地区（克里米亚、顿卢分离区、古巴、伊朗、朝鲜、叙利亚）（C2，GitHub Docs 转引，[待核实]）。OFAC 制裁名单（SDN List）具体条目数待研究（草图未覆盖，正式拆解需查 OFAC 原始数据）。

## 方向、两条流、争夺事件

### 拒绝方 / 操作方

拒绝方：国家（主权），及被拉来执行的平台（所有权）。这层控制主要靠国家的强制力和平台的合规系统运转，前者是自上而下的封锁，后者是自动化的地理围栏，**都不依赖大量一线工人的持续配合，因此几乎没有操作方从内部反向施力的空间**。唯一的例外线索是电信运营商员工在极端情况下的不配合，但在国家强制下这种力量很弱（待验证）。

### 最近一次被争夺的事件

2019 年 7 月起，GitHub 依据美国出口管制与制裁法律，限制伊朗、叙利亚、克里米亚等地开发者的账户功能（付费功能、私有仓库等）（C2，TechCrunch 2019 / GitHub Docs 转引）。据报道，npm（同属微软/GitHub）也对伊朗账户做类似限制，从伊朗发布软件包被有效阻断，但下载软件包因被视为"公开可得信息"通常仍可进行（C2，媒体转引，[待核实]）。后来 GitHub 拿到 OFAC 许可，得以恢复对伊朗开发者的部分服务（C2，developer-tech 转引，[待核实]）。这个案例把这层控制的特点摆得很清楚：一条制裁规则，通过美国法域内的平台，自动按地理位置把一整国的开发者挡在门外，误伤大量与制裁目标无关的普通人；而"下载可以、发布不行"这种细分，又显示执行方在合规和可用之间反复拿捏。

## 数据缺口清单

正式拆解时需补的一手件：

1. Access Now / KeepItOn《2024 年断网年报》原文（PDF），核对次数、国别与触发原因分类。
2. 美国 OFAC 制裁法规原文与 SDN List 条目统计（财政部官网）。
3. GitHub《贸易管制》政策原文（site-policy）与获批 OFAC 许可的官方公告。
4. npm 的制裁合规政策原文，核对"发布被阻、下载可行"的准确边界。
5. 中国国家级防火墙的技术与制度依据研究（第三方测量报告，如 OONI）。
6. OONI / Censored Planet 等对各国过滤的实测数据，把"封了什么"落到可查证的测量上。
7. 具体的开源项目/服务因 OFAC 地理封锁下架的公开案例清单，评估误伤规模。
8. VPN/绕行工具在高强度封锁下的实际可用性研究，判断退路是否真成立。
