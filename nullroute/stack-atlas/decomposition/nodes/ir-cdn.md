> 建立：2026-07-26（定时任务，一轮一个节点、本人写）。Phase 4，互联网可达性栈 ir。
> 合并说明：子节点登记表里的 ir-cloud-cdn（2026-07-23 由 ir-cloud 登记）与本节点是同一层，本轮定夺为并入本节点。合并方向与 ir-cloud 节点第 5 维当时的建议（以子节点吸收 ir-cdn）相反，理由：主表 79 节点的统计口径不动、ir-cdn 在计划里登记在先，内容放哪边都一样，动账目最小的方案优先。ir-cloud-cdn 在登记表标注并入，不再单独拆。

## 与相邻节点的分工（先立这个，立不住整张矩阵白做）

- ir-cloud（已建，2026-07-23）管"一个服务在互联网上可达/被下线"的四接口控制面总图，CDN+DDoS 缓解只是其中一个接口，它的争夺事件读的是平台下线（Cloudflare 撤 Kiwi Farms 防护）。那半边的结构（撤保护即下线、行业内容治理趋同、以不作为完成拒绝）已在 ir-cloud 写透，本节点引用、不重复。
- 本节点管 CDN 这一层自身的另一半：它同时是审查规避的屏障。反向代理终止用户与站点之间的加密连接、把海量站点混在同一批共享 IP 后面，审查者要封其中一个站点，技术上就得连带封同一批 IP 后面的所有站点。这个物理形态使 CDN 天然挡在国家审查装置前面。于是本节点的争夺方向与 ir-cloud 相反：不是 CDN 拒绝站点，而是主权从外部拒绝 CDN。争夺事件读俄罗斯监管方对 Cloudflare 的封锁与限流（2024 至今，正在进行）。
- ir-filter（待填）管国家审查装置本身（深度包检测、封锁清单、断网开关）。俄罗斯装在运营商机房里的"技术威胁对抗装置"（ТСПУ，按 2019 年主权互联网法部署的在径深度包检测设备）是那个节点的主体，本节点只记它作用于 CDN 的这一面，装置本身留给 ir-filter 拆。

## 结构层（11 维）

### 1. 功能定义

CDN（内容分发网络）加 DDoS 缓解，合起来是"反向代理层"：站点把自己的域名指到代理商的边缘网络上，用户的请求先到代理商的就近节点，代理商终止加密连接、缓存内容、吸收攻击流量，再把干净流量转给源站。这一层卡两样东西。对站点，它卡"扛不扛得住"：大流量站点和被攻击目标离开这层防护就下线，这半边在 ir-cloud。对审查者，它卡"看不看得清、封不封得准"：加密终止在代理商手里，站点藏在共享 IP 池后面，审查装置无法只封一个站点而不伤同批其余站点。绕不开的属性锚在网络规模效应（节点越多、吸收攻击能力越强）加免费入口层造成的海量默认采用。

不做什么：不管托管账户、身份与访问管理、应用商店分发（ir-cloud 的另外三个接口）；不管域名解析与证书信任（ir-dns）；不管审查装置内部构造（ir-filter）。

### 2. 物质形态与可运输性

比特加服务。物理上是分布在全球几百个城市的边缘服务器集群（Cloudflare 自称覆盖约 330 个城市，C3，公司口径），靠任播路由（同一个 IP 地址从全球多点宣告，用户被路由到最近节点）把流量吸到边缘。这个形态决定了两件事：第一，它没有单一的物理位置可占领，主权方够不到它的"厂房"；第二，它的服务必须穿过用户所在国运营商的管道才能到达用户，所以主权方虽然摸不到它的服务器，却可以在自己境内的管道上把它拦下。俄罗斯 2025 年的做法正是后者：不碰 Cloudflare 的任何资产，在本国运营商的在径设备上把发往它的连接掐到 16KB。

### 3. 供给集中度

分口径。在"使用反向代理的站点"里，Cloudflare 约占 80%（W3Techs 口径，C3，注意分母是用反向代理的站点、不是全体网站）；按全体网站算，约 20% 的网站在 Cloudflare 后面（C3，Cloudflare 自称口径与 W3Techs 大致相合）。企业级高端市场 Akamai、Fastly、Amazon CloudFront 份额更高，Cloudflare 主导的是长尾。access maker 是 Cloudflare：它决定免费层收谁、撤谁，也因为体量成了审查者眼里"封 CDN 等于封五分之一个网"的那道墙。

### 4. 主要持有者 + 份额 + 法域

| 主体 | 位置 | 份额/规模 | C 等级 | 法域 |
|---|---|---|---|---|
| Cloudflare（NYSE: NET）| 反向代理长尾主导 | 反向代理站点约 80%（W3Techs）；FY2025 营收约 21.6 亿美元 | C3 | 美国 |
| Akamai（NASDAQ: AKAM）| 企业级老牌 | FY2024 总营收约 40 亿美元，其中传统分发业务约 11–12 亿且逐年收缩，重心已移向安全与算力 | C3 | 美国 |
| Fastly（NYSE: FSLY）| 高端可编程 CDN | FY2024 营收约 5.4 亿美元 | C3 | 美国 |
| Amazon CloudFront | 云捆绑 CDN | 不单独披露【缺口：需要 AWS 10-K 分部附注或 Synergy/Gartner 拆分报告】 | — | 美国 |
| 俄境内替代：NGENIX（Rostelecom 系）、EdgeCenter 等 | 俄罗斯本国 CDN | 份额【缺口：需要俄行业报告或 Roskomnadzor 登记名录】 | — | 俄罗斯 |

法域结论与 ir-cloud 相同：全球反向代理层的主要供给方全部在美国法域。这正是俄罗斯把"境内可达性"从这层夺回去的动机之一。

### 5. 上游依赖（子节点）

- BGP 路由宣告（ir-bgp）：任播的成立前提是全球运营商接受代理商的路由宣告。主权方在境内改路由、或运营商拒收宣告，任播在该国即失效。俄罗斯限流正是在这一层与传输层动手。
- 海底光缆与国际出口（ir-cables）：边缘节点回源要走国际链路；一国国际出口越集中，在径拦截越容易。
- IP 地址与证书：共享 IP 池（编号资源，经区域互联网注册机构分配）与 TLS 证书（ir-dns 的 CA 体系）。加密客户端问候（ECH，把用户要访问哪个域名也加密掉的 TLS 扩展）是本节点与审查装置冲突的直接引信。
- 不再单列子节点：ir-cloud-cdn 已并入本节点。

### 6. 下游依赖方

- 挂在反向代理后面的全球站点（约占全体网站两成，C3）：对防护是致命依赖（见 ir-cloud 第 6 维），对"俄罗斯境内用户还能不能到达自己"在 2025-06 之后变成被第三方决定的事：站点自己什么都没做错，也没被 Cloudflare 撤服务，照样在俄境内变得几乎不可达。
- 俄罗斯境内用户与本国中小企业：ЦМУ ССОП（公用通信网监测与管理中心，隶属 Roskomnadzor）2024-11-07 通告原文直接"建议信息资源的所有者……使用国产 CDN 服务"，等于官方承认打击面首先落在本国站点上（C4，原文已入库 `raw/stack-atlas/ir-cdn/cmu-rkn-2024-11-07-cloudflare-ech.html`）。
- 依赖强度：全球站点对俄境内受众，可缓冲（损失一国市场）；俄本国挂 CF 的站点，致命（要么弃用防护迁回国内 CDN，要么对本国用户不可达）。

### 7. 替代路径 + fallback 等级

分三个当事方问，答案不同。

- 站点换代理商（Cloudflare 换 Akamai/Fastly）：普通站点 operational，小时级到天级（与 ir-cloud 第 7 维一致）；争议站点 blocked（行业内容治理趋同，见 ir-cloud）。
- 俄罗斯站点的退路：迁回本国 CDN（NGENIX、EdgeCenter 等）。五问：替代的是分发与基本防护层；接上以周计；转换不过去的是抗大规模 DDoS 的吸收容量（网络规模效应堆不出来）与全球受众触达；启动权限在站点自己；现场执行能力存在（俄境内 CDN 在运营）。判 partial：国内可达性能接回，防护深度与全球触达接不回。这条退路正是限流方想逼出来的结果，Cloudflare 流量在俄 2025-06 起降约三成（C3，俄媒转引），说明退路在被真实走通。
- 全球站点对俄受众的退路：几乎没有。列 blocked：拦截发生在用户侧国家的管道里，站点与代理商都够不到，Cloudflare 官方博客明说此事在其控制之外、无法以合法方式恢复（C4）。**07-30 新增两条线索，但均不足以把这条判断从推断升为有旁证**（当日两道门指出后订正，原写"补到直接旁证"给高了）：一是 2025-03-20 那轮封锁里 Amazon 与 Fastly 的服务同受影响（C3，经 HRW 转述自 Roskomsvoboda，报告页 17）——报告只有一句话，"服务受影响"与"换成 Fastly 同样会被主权拦下"之间还差着机制（共享 IP 段连带、这两家自己也挂 Cloudflare、俄方另有独立动作，三种都能产生"受影响"），且与本行现有支撑不同层（Hetzner、DigitalOcean 是托管商、不是内容分发网络）；**回填升级前须先取 Roskomsvoboda 原文**。二是 2024-12 Roskomnadzor 点名威胁的八家外国托管商（GoDaddy.com、Amazon Web Services、HostGator.com、Kamatera、Ionos、Network Solutions、DigitalOcean、Hetzner Online；C3，经 HRW 转述自 Vedomosti 2024-12-07，报告页 17）。此前本行写的"Hetzner、DigitalOcean、OVH"里 **OVH 不在这份名单上，来源待核**。

### 8. 重建壁垒 + 前置期

复制一张全球反向代理网络：資本与年头都在其次，真壁垒是两条。其一，网络规模效应，吸收攻击的容量随节点数与总带宽长，追赶者在防护深度上长期落后；其二，免费入口层的既有装机量，两成网站已经挂在上面，替代者做得出网络、越不过"无人迁移"这道坎（领域核第四节来历维：网络效应型来历的标准模式）。对主权方，重建的不是网络而是"境内可控的等价物"：俄罗斯用行政压力加管道拦截把本国站点赶进国内 CDN，等于用强制在自己领土上重建这一层，前置期以年计，且只在境内成立。

### 9. 议价 / 控制机制

卡点 type：service 加 information。卡点 mode 按方向分：代理商对站点，平时 open，争议站点 selective-seizure，行业趋同时 near-closure（此半见 ir-cloud）；主权方对代理商，俄罗斯路径是 selective-seizure（先只封 ECH 站点）滑向 near-closure（16KB 限流事实上使全体挂 CF 站点在俄不可用）。控制靠什么执行：代理商靠服务条款与账户状态；俄方靠在径设备做包注入与丢包（C4，Cloudflare 博客列明手法），不需要任何法律文书送达对方，也不发正式声明。这是领域核第四节拒绝权来源之外的第三种位置的干净样本：既不拥有也不运营这个环节，占据通道旁侧（本国运营商机房），从外部中断流动。

### 10. 历史变迁（卡点怎么移动）

- 1998 起：Akamai 开创企业级 CDN，按流量收费，纯商业收费站。
- 2010 年代：Cloudflare 用免费层把反向代理推成长尾默认配置，防护从奢侈品变成基础设施；代理层顺带成为审查规避的事实屏障（域名前置时代，规避工具借大平台域名藏身）。
- 2018-04：俄罗斯为封 Telegram 一度封掉数以百万计的 AWS/谷歌云 IP，殃及大批无关服务（C3）；同月 Amazon 与 Google 主动禁掉域名前置（C3）。这一轮照出的结构：审查者第一次大规模试探"封云就得连带封网"，平台方选择自己拆掉规避屏障的一角。
- 2022：俄乌开战后 Cloudflare 拒绝退出俄罗斯，公开理由是俄罗斯需要更多而不是更少的互联网接入（C3）。代理层第一次明确把自己摆在审查装置的对面。
- 2024-10：Cloudflare 默认开启 ECH（ЦМУ ССОП 通告自述，C4）。2024-11-05：俄用户开始报告数千个启用 ECH 的站点访问异常（C3，HRW 报告）。2024-11-07：ЦМУ ССОП 发布官方通告，定性使用 ECH"违反俄罗斯法律"、明写限制由 ТСПУ 执行、劝俄站点改用国产 CDN（C4，原文已入库；先封后告，官方文件是对既成动作的追认）。
- 2025-03-20：多地区多运营商下 Cloudflare IP 不可达，乌拉尔与西伯利亚最重，波及 TikTok、Steam、俄本国银行与政府门户等；受访专家称之为评估中断范围的一次试验，全面封锁当时是预期而非事实（C3，The Record 2025-03-20）。**同一轮的另一组波及站点（C3，经 HRW 转述，报告页 32；该处脚注为 Taimlain Runeta 时间线与 DownDetector 俄站 Wayback 快照，07-30 精读补）：YouTube、Duolingo、Twitch；2025-03-24 用户报告无法使用俄罗斯最大银行 Sberbank 的应用（同页，该条脚注为 Meduza）。** 同轮**不止打到 Cloudflare**：Amazon 与 Fastly 的服务同受影响（C3，经 HRW 转述自 Roskomsvoboda，报告页 17；仅一句转述，见第 7 维的限定）。Roskomnadzor 当时的公开归因是受影响网站所用的"外国服务器基础设施"故障，并建议改用俄罗斯服务器（C3，经 HRW 转述，报告页 32；该处脚注为 RBC 的电报频道帖、非官方声明原文）——见下方 F 维。
- 2025-06-09 起：16KB 限流（见争夺事件）。
- 2026：zona.media 2026-04-07 文与其他报道称限制进一步收紧（C3 检索摘要级，原文 403 未读，日期与范围待核。订正：先前此行写"2026 年全面封锁、主流网站变暗"，经核 The Record 那篇发表于 2025-03-20 且自述为部分中断，原记录疑将其错记为 2026 年全面封锁，降为待核）。
- 轨迹读法：卡点从代理商手里（收谁撤谁）向用户侧主权手里（放行多少字节）移动了一半。移动的工具不是夺取所有权，是在自己领土的管道上另造一个在径节点。

### 11. 因果层

real force 为主：两成网站的既有绑定加网络规模效应，是代理商力量的根。但本节点新照出的一层是，这个 real force 在领土边界处失效：绑定得再深，最后一公里的管道归属地主权，攻击者不需要碰任何 real force，只需要在管道上丢包。调用技巧层（俄方选择不发声明、不出文书、由运营商静默执行，使"是否在封锁"成为需要外部测量才能确认的事）是这场争夺里的显著变量。

## 量化层（6 项）

> 口径说明：市场规模与玩家财务与 ir-cloud Q1/Q3 部分重叠，此处只列本节点承重的数字，不重复计价。

### Q1. 市场规模
全球 CDN 市场约 200–250 亿美元/年（2023，C2，Grand View / Mordor 商业报告口径，原文未核，与 ir-cloud Q1 同源同缺口）。DDoS 防护市场单独口径约 40–60 亿美元/年（C2，MarketsandMarkets 类报告，待原文）。

### Q2. 集中度量化
反向代理站点口径 CR1（Cloudflare）约 80%（C3，W3Techs）；全体网站口径 Cloudflare 约 20%（C3）。营收口径集中度低得多：Akamai 40 亿、Cloudflare 21.6 亿、Fastly 5.4 亿（C3），营收 CR3 在 CDN 市场约三至五成（C2 推算，取决于市场规模口径）。两个口径的反差本身是结构信息：Cloudflare 用免费层拿走了站点数、没拿走对应营收，price maker 是它（免费入口压平整个长尾市场定价，与 ir-cloud Q2 一致）。

### Q3. 关键玩家财务概况
- Cloudflare：FY2025 营收约 21.6 亿美元（C3，待 10-K 升 C4），FY2024 约 16.7 亿美元（C3）；长期低毛利换增长，市值数百亿美元量级（C3，随行情波动）。
- Akamai：FY2024 营收约 40 亿美元（C3），传统分发分部逐年收缩、安全与算力分部为主（C3，待 10-K 分部数据）。
- Fastly：FY2024 营收约 5.4 亿美元（C3），市值十亿美元量级（C3）。
- 资本纵深判断：三家都不靠俄罗斯市场（Cloudflare 2022 起已暂停在俄销售，C3），俄方限流对其资产负债表冲击接近零。这解释了为什么这场争夺里代理商只发技术博客、不谈判：没有可被要挟的经济敞口。

### Q4. 下游依赖度量化
- 站点对本节点：防护与分发占中小站点 IT 成本比例低（免费层为零），但对可达性是全有全无（与 ir-cloud Q4 一致）。
- 俄罗斯场景的新量化：限流影响俄境内用户对约两成全球网站的访问（C3/C4，Cloudflare 称影响所有经其网络的资产、外媒以其份额推为约 20% 互联网）；俄境内 Cloudflare 流量 2025-06 起降约 30%（C3）。
- 库存/在途缓冲：零。可达性没有库存。

### Q5. 断供 / 管制的经济冲击量级
- 单一代理商全球故障的系统性冲击已有实测：2021-06 Fastly 配置错误使全球大批主流网站同时下线约 1 小时（C4，已在 ir-cloud Q5，此处引用不重复）。
- 俄式管道拦截的冲击量级：受影响的是俄境内约 1.4 亿网民对两成外网的正常访问（C2 推算量级），直接经济损失无权威估算【缺口：需要俄行业协会估算或独立经济测算。**07-30 更新：HRW 2025-07 报告已排除**——全文没有任何经济损失量化，它是人权报告，关心权利受损不关心金额，本轮精读时全文搜过】。冲击的承受方主要是俄本国用户与站点，代理商财务几乎无感（见 Q3）。这个不对称正是此类拒绝能持续的原因。

### Q6. 资本流向与利润归宿
长尾利润被免费层压平、企业级利润沉在 Akamai/Fastly 大客户合同（与 ir-cloud Q6 一致）。本节点补一条：俄罗斯限流把俄境内的分发生意从美国代理商的免费层赶进本国收费 CDN，利润归宿随主权拦截发生转移，受益方是 Rostelecom 系等国内运营商。这个转移是被有意安排的、不是外溢：ЦМУ ССОП 2024-11-07 通告在同一份文件里做了两件事——宣布限制、推销替代品（劝用国产 CDN，并给国家反 DDoS 系统 НСПА 附上"自 2024 年 3 月起抵御超 1.05 万次攻击"的运行数据）（意图 C4，原文；转移金额仍 C2，待俄行业数据）。政治压力打不到美国代理商的资产负债表，打到的是被迫二选一的俄本国站点的成本表。

## 政治传动层（6 维）

### A. 公开接口
- 俄方：2019 年主权互联网法（联邦法 90-ФЗ）授权在运营商网络部署"技术威胁对抗装置"（在径深度包检测设备）；2021 年落地法（236-ФЗ）要求外国互联网公司在俄设立代表处，2025-04 Roskomnadzor 以此威胁封锁不合规的外国托管商（C3）；ЦМУ ССОП 2024-11-07 官方通告《Рекомендуем отказаться от CDN-сервиса CloudFlare》（C4，原文已入库，经 Internet Archive 当日快照取得；通告明写限制由 ТСПУ 执行——ir-cdn 与 ir-filter 之间那条边的一手文书）。
- 美方：OFAC 制裁名单，代理商对被列名实体终止服务（C3，此半在 ir-cloud/ps-sanctions）。

### B. 控制状态流转
俄境内对 Cloudflare：默认通行（2022 前）→ 对启用 ECH 的站点拒绝（2024-11，allow by exception 的变体：关掉 ECH 才放行）→ 部分地区 IP 级不可达试验（2025-03-20，C3）→ 全面限流、事实上的拒绝推定（2025-06 起，16KB 等于放行握手、拒绝内容）→ 进一步收紧（2026，报道级待核）。翻转门槛：Roskomnadzor 单方技术动作，不经法院、不发正式命令，由运营商在径设备静默执行。谁有权翻：监管方一家，且可无级调节（字节数就是旋钮）。

### C. 适用账本
许可账（ECH 关不关、落地法合规与否）加收费时点账的变体：限流不是关断，是把"放行多少"变成连续变量，监管方第一次拿到了对外国基础设施的模拟量控制，而不只是开关量。

### D. first payer
俄罗斯本国用户（约 1.4 亿网民失去对两成外网的正常访问）与俄本国挂 CF 的中小站点（被迫迁移或失去本国受众）。全球站点损失俄市场居次。代理商几乎不付代价（Q3）。这个次序是设计出来的：打击面越偏向本国，越能把本国站点赶进国内替代品。

### E. 时点
2024-10 Cloudflare 默认启用 ECH（C4，通告自述）；2024-11-05 用户开始报告 ECH 站点被封（C3，经 HRW 转述；**该处脚注指向的 NTC.party 论坛帖日期为 2024-08-07，比它支撑的事件早三个月，待核**）；2024-11-07 ЦМУ ССОП 官方通告（C4，原文）；2025-03-20 部分地区 IP 级不可达（C3）；2025-06-09 限流开始（C4，Cloudflare 博客）；Cloudflare 发博客确认并披露手法（C4；**发布日期待核**，HRW 正文记 2025-06-26、其脚注记 2025-07-15）；2026 年进一步收紧（C3，日期待核）。

### F. 叙事合法化
俄方叙事：ECH 等加密技术"违反俄罗斯法律"、威胁网络主权；更大框架是主权互联网（Рунет 自主可控）。**07-30 补一条此前没有的官方归因动作**：2025-03-20 大面积中断发生后，Roskomnadzor 把中断说成受影响网站所用"外国服务器基础设施"的故障，并建议改用俄罗斯服务器（C3，经 HRW 转述，报告页 32；**该处脚注指向 RBC 的电报频道帖，不是官方声明原文**）。三步的做法是：在自己境内的管道上造成一次中断 → 把原因归给境外那一层基础设施 → 同时把国产替代品作为解决办法推出去。ЦМУ ССОП 2024-11-07 通告（C4，原文已入库）是同一套在 CDN 这一层的更早一版（宣布限制、同时劝用国产 CDN）。**证据地位（07-30 两道门订正后）：只有 CDN 这一例三步齐全。** 国家域名系统那一层（2024-01 `.ru`/`.рф` 大面积故障被归因于全球 DNSSEC 更新、同时建议切换到国家域名系统）缺第一步——HRW 报告只说用户报告了中断，没有任何一处说是当局造成的；而且那次故障的技术成因待核（公开报道多归为 `.ru` 区自身的 DNSSEC 签名或密钥错误，若如此则"归因 DNSSEC"是正确的技术说明、不是推锅）。托管那一层只有威胁封锁、无中断无归因，不构成实例。**所以这个模式目前是"一例完整、一例待核"，不足以立为规律，不据此改动本节点任何判断。** 分析与逐案核查见 `wiki/reading-workbench/2026-07-30-ir-cdn-HRW俄罗斯审查报告精读.md` 第二节。动员对象是国家安全叙事下的立法与技术机构，不需要动员公众（执行是静默的）。Cloudflare 方叙事：开放互联网、"俄罗斯用户无法访问开放互联网"（博客标题即立场）。两套叙事都在为各自的下一步动作铺路：一边为全面封锁，一边为把责任钉在俄方。

## 方向（拒绝方 / 操作方）

- 拒绝方一：代理商（Cloudflare 等），凭所有权与服务条款拒绝站点。此半在 ir-cloud。
- 拒绝方二：美国主权，经 OFAC 命令代理商执行拒绝（国家施压、运营者执行的标准组合）。
- 拒绝方三（本节点主角）：用户侧主权（俄罗斯），既不拥有也不运营，占据本国管道旁侧从外部中断流动，是领域核第四节第 5 维那第三种位置。它的拒绝权来源是领土主权对境内物理管道的控制，执行装置是运营商机房里的在径设备。
- 操作方：弱。代理商网络高度自动化、运维人员少而分散，无集体行动杠杆（operating-layer 三问全不满足，与 ir-cloud 判断一致）。俄方执行链上的"操作方"是五大运营商，但它们是被主权强制的执行者、不是能扣住配合反过来议价的一方（运营商若不装在径设备即违法），不构成概念卡意义上的操作方力量。

## 两条流

信息流为主：本节点是信息流上"可见性与可达性"的双向中断点。代理商方向切的是站点的可达性（撤防护）；主权方向切的是本国用户的可达性（限流），同时夺回可见性（ECH 被封，因为它让审查装置看不见用户要去哪个域名，领域核第二节信息流"能被看见即能被监控"的反向应用：看不见即不许过）。价值流很薄（免费层压平，见 Q6）。物理流不涉及。

## 最近一次被争夺的事件（2024-10 至今，正在进行）

事件：俄罗斯监管方对 Cloudflare 的分级拒绝，从封 ECH 站点（2024-11）到 IP 级不可达试验（2025-03-20）到 16KB 限流（2025-06-09 起），2026 年报道称进一步收紧（待核）。

五个阅读动作：

1. 校准颗粒度：争的不是"CDN 市场"，也不是哪一个站点，是"俄罗斯境内用户与全球反向代理层之间的管道"这一段。Cloudflare 的全球网络毫发无损，被争夺的是它在一国领土上的效力。
2. 反应链：Cloudflare 默认开启 ECH（2024-10）→ ECH 站点被封（2024-11-05 起）→ ЦМУ ССОП 发通告定性违法、劝俄站点弃用 CF（2024-11-07，C4）→ 俄五大运营商部署 16KB 限流（2025-06-09）→ Cloudflare 拒绝俄方曾经的落地要求、发博客公开手法与立场、声明无法恢复（日期待核，见 C 等级清单）→ 俄站点成批迁往国内 CDN（流量降三成）→ Hetzner、DigitalOcean、OVH 等外国托管商同受限制（C3）。反应链暴露的当事方：Cloudflare、Roskomnadzor、五大俄运营商、俄本国站点主、国内 CDN（受益方）、其他外国托管商（同批目标）。
3. 被当成地面的一方：俄罗斯本国站点主与用户。主流叙述把这场争夺讲成俄国家对美国公司，但真正被碾过的是挂在 CF 后面的俄本国站点，它们有自己的决定性一手吗？有一个弱的：迁移。它们迁得越快，限流的国内代价越小，监管方越敢收紧；迁移本身成了监管方计划的一部分。没有集体抵抗的迹象（C3，未见俄行业组织公开反对的报道，此判断弱、留观察）。
4. 放到时间里读：2018 封 Telegram 时俄方还只会大水漫灌封 IP、社会代价大到收手；2024 起改用在径设备做精细分级（先 ECH、再 16KB、再收紧），同一个监管方六年里从开关量升级到了模拟量。控制权没有换手，但控制的分辨率换代了。
5. 说法和数字当动作：Cloudflare 的"16KB、10 到 14 个包、五家运营商、包注入手法"这组数字是受损方生产的测量（C4 作为"Cloudflare 观测到什么"，但它同时是把责任钉给俄方的动作）；Roskomnadzor 系统对 2024-11 的 ECH 封锁发了正式通告（并借机推销国产替代品），对 2025-06 的 16KB 限流却始终沉默——同一个监管方，宣布哪些动作、对哪些动作保持可否认，本身是分开拿捏的手法；"ECH 违反俄法律"是把技术特性翻译成违法行为的归类动作（以归类完成拒绝的变体）。

争夺照出的结构：反向代理层的力量建立在"封我就得连带封五分之一个网"这道数学题上，俄方的回答是接受这道题、把连带损失全额转嫁给本国站点并借势完成进口替代。当一个主权方愿意付出这个代价时，CDN 的规避屏障在其领土内失效。这场争夺同时给 ir-filter 节点留了主体（在径装置），给"技术形态影响政体"（领域核第五节）添了一个反向样本：中心化的在径审查装置使模拟量级的信息主权成为可能。

## 卡点分析

- 位置：ir 栈 L1 逻辑控制层，反向代理段。
- 持有者：Cloudflare 为主的美国代理商（对站点方向）；用户侧主权（对领土内可达性方向）。
- 卡点来源：网络效应 + 规模经济 + 免费入口装机量（代理商侧）；领土主权 + 在径装置（主权侧）。
- 政治进入后转移：正在发生。俄案例显示主权方不夺取节点、而在自己领土上使其失效并催生国内替代，控制权按领土碎片化。时间估计：俄境内的转移已过半（流量降三成），其他威权法域是否复制此法待观察（不预测，只记：手法已公开可抄）。
- 干预窗口：对代理商侧的内容治理趋同，窗口在 ir-cloud 已记。对主权侧拦截，站点与代理商都无干预手段（Cloudflare 自认无法恢复），唯一的外部干预点是把限流成本变成俄方可感的政治议题（HRW 等报告在做的事），效果未证。
- 最硬反例 + 过三关："CDN 集中不是真卡点，因为换 CDN 只要几小时。"三关：前提成立（技术可换、普通站点确实 operational）；可比性不成立，反例只覆盖"站点换代理商"这一个方向，本节点的争夺发生在另外两个方向（争议站点被行业趋同封死、主权在管道上拦截时换哪家都一样被拦，五家俄运营商拦的是发往 Cloudflare 的连接，换成 Fastly 同样可拦且 Hetzner 等已同受限制）；真发生过（Kiwi Farms 换到哪家哪家撤，俄限流对全体挂 CF 站点无差别）。结论：反例只证明"分发"可替代，不触及"防护深度"与"领土内放行权"两个真卡点。

## 级联关系

- 上游来自：ir-bgp（任播依赖路由宣告）、ir-cables（回源链路）、ir-dns（证书与 ECH 的 DNS 配套，ECH 的公钥经 DNS 分发，封 ECH 与 DNS 层联动）。
- 下游影响：全体挂反向代理的站点的可达性；俄境内互联网的对外开放度。
- 跨栈耦合：ps-sanctions（OFAC 经代理商执行拒绝）；ir-filter（在径装置是本节点主权侧拒绝的执行体，待填节点的直接输入）；ir-cloud（同一层的平台下线方向）。
- 跨域效应：法玛的域（平台治理与言论基础设施）；牵星的域（威权政体的信息控制升级路径，16KB 模拟量控制是精英对社会的新型控制工具）。
