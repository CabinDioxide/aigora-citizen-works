# 节点 ir-cloud：云控制面（托管 / CDN / DDoS 缓解 / IAM / 应用分发）

> 父节点：ir（互联网可达性栈）| 层：L1 逻辑控制（可达性执行面）
> 建立：2026-07-23 | 数据综合 C：C2–C4（Parler/AWS 停服 C4；Cloudflare–Kiwi Farms 撤保护 C4；维基解密停服 C4；IaaS 市场集中度 C3；Cloudflare 反向代理份额 C3；各公司财务 C2–C3 待年报核）

---

## 与相邻节点的分工（先划清，否则整张矩阵错位）

这个节点最容易和已建的 ir-dns、ac-cloud 混。先把边界定下来。

- ir-cloud vs ir-dns：两者都在 ir 栈的 L1 逻辑控制层，但卡的接口不同。ir-dns 管的是命名和信任，域名能不能被解析（DNS 根区）、HTTPS 证书受不受信任（CA trust store）。ir-cloud 管的是托管、分发和防护，服务器在哪里跑（IaaS 托管账户）、内容怎么送到用户面前（CDN）、能不能扛住攻击而不掉线（DDoS 缓解）、进入这些资源的钥匙是什么（身份与访问管理，IAM）、移动端 App 能不能被装到手机上（应用商店分发）。一个平台被彻底"下线"，通常不是单点动作，而是几个接口同时被撤：DNS 撤（ir-dns）+ 托管账户封（ir-cloud）+ CDN/DDoS 盾牌撤（ir-cloud）+ 应用商店下架（ir-cloud）+ 支付通道切断（fi-card / fi-stablecoin）。ir-cloud 负责这叠接口里"托管，分发，防护，身份"这四个。

- ir-cloud vs ac-cloud：这两个节点共用同一批公司（AWS、Azure、GCP），但卡的对象完全不同。ac-cloud 卡的是"谁能用 GPU 算力"，AI 训练和推理的算力供给，政治接口是 EAR 出口管制（3A090.a、4E091）。ir-cloud 卡的是"谁能在互联网上被访问到"，一个网站、服务或 App 的可达性，与算力无关。同一家 AWS，对一个 AI 实验室是算力供应商（ac-cloud），对一个新闻网站是托管+可达性的控制面（ir-cloud）。分开拆是因为两者被激活的政治机制、first payer、叙事都不同：ac-cloud 是国家安全出口管制，ir-cloud 更多是平台 ToS 内容治理和主权国家的境内封禁。

- 不负责：GPU 算力供给（ac-gpu / ac-cloud）；域名解析与证书（ir-dns）；物理光缆与 IP 路由（ir-cables / ir-bgp）；国家防火墙的内容过滤（ir-filter，那是主权方在自己境内对入境流量做过滤，ir-cloud 是全球控制面把一个服务从源头下线，方向相反）。

## 结构层

### 1. 功能定义

云控制面是"一个服务在互联网上存在并可达"所必须经过的一叠接口。它不是单一环节，而是四个必经接口的合称：

1. IaaS / PaaS 托管：服务器在谁的机房里跑。没有托管，服务没有运行的地方。账户被封，服务当天下线。
2. CDN（内容分发网络）：把网站内容缓存到全球各地的边缘节点，让用户就近取，降低延迟、分担源站压力。对大流量站点，CDN 不是可选项，没有它，源站扛不住正常流量。
3. DDoS 缓解：抵挡分布式拒绝服务攻击（大量僵尸机同时涌向一个站点、把它的带宽和连接数打满）的盾牌。对任何有敌人的站点，撤掉这个盾牌，第三方的攻击会在几小时内把它打下线，控制方本身不必动手。
4. IAM（身份与访问管理）：进入以上资源的凭证体系。账户登录凭证是唯一的钥匙，凭证被撤，人就进不去自己的资源。

这四个接口卡的共同属性是内容可达性：一个服务的域名还在、证书还有效（那是 ir-dns 的事），但如果没有地方托管、没有分发、扛不住攻击、或者账户进不去，它在互联网上就等于不存在。这个节点的"绕不开"锚在，对绝大多数商业和媒体服务而言，自建全球托管+CDN+抗 DDoS 基础设施的成本高到不现实，只能租用少数几家提供商的控制面，而租用关系的另一端是一份可被单方面终止的服务条款（Terms of Service, ToS）。

它不做：不决定域名能不能解析（ir-dns）、不决定 GPU 算力谁能用（ac-cloud）、不在主权边界上过滤入境内容（ir-filter）。

### 2. 物质形态与可运输性

比特+合同许可，运行在真实的物理数据中心和边缘节点网络上。物质形态和 ir-dns、ac-cloud 同类，控制的执行不靠物理截断，靠账户状态和服务条款。

- 托管资源不可远程迁移，但访问可路由：数据中心和边缘节点的物理位置固定，但用户的访问路径可以任意路由。控制方不需要动任何物理设施，只需在账户后台把一个客户的服务停掉。
- 账户即访问：和 ac-cloud 一样，账户凭证是唯一进入资源的钥匙。封禁账户 = 服务下线，不需要任何物理动作，生效速度以小时甚至分钟计。
- DDoS 缓解层有一个独特的物质形态：它的"下线"机制不是控制方主动切断，而是控制方停止提供防护（不作为），实际的打击由第三方的 DDoS 攻击完成。控制方的动作是"撤走盾牌"，打击者是别人。这一点使 DDoS 缓解层在拒绝权的机制上和其他三个接口不同（见"方向、两条流"一节）。

这一物质形态决定了拒绝权的执行方式：暂停账户、终止服务条款、或撤走防护，三种动作都不需要物理行动，都能在天级以内生效。Parler 案（AWS 2021-01-10 依 ToS 违规终止托管，服务约 36 小时后下线）是最清晰的实证，C4，双方法律文件均可查。

### 3. 供给集中度

四个接口各有集中度，整体是"少数美国公司主导 + 一个接口近独占"的结构。

IaaS / PaaS 托管：三家美国 Hyperscaler 主导

沿用 ac-cloud 的份额（Synergy Research 口径，C3）：AWS、Azure、GCP 三家合计约占全球云 IaaS 市场 60–65%（CR3，C3）。次级玩家 Oracle、IBM、阿里云（阿里云在国际市场份额小）。对一个需要下线的目标而言，托管可以在三家之间迁移，不是单点，但三家都在美国法域、都用同一套 ToS 逻辑，迁移不改变"落在美国平台治理下"这个事实。

CDN + DDoS 缓解：Cloudflare 近独占反向代理层

这是四个接口里集中度最高、也最隐形的一个。Cloudflare 在"使用反向代理的网站"中占约 80%（W3Techs 口径，C3，注意这是"使用反向代理的站点里用 Cloudflare 的比例"，不是全体网站里的比例，两个口径差别大，须谨慎）。其余为 Akamai、Fastly、Amazon CloudFront、Google Cloud CDN、Imperva 等。Cloudflare 的特殊性在于：它把 CDN、DDoS 缓解、WAF（Web 应用防火墙）、DNS 打包成一个免费/低价的入口层，海量中小站点默认挂在它后面，这使它成为"撤保护即下线"这个动作射程最广的一家。

IAM：绑定在托管平台内

IAM 不是独立市场，是每家托管平台内建的凭证体系（AWS IAM、Azure AD/Entra ID、Google Cloud IAM）。集中度跟随托管层，不单独计。

应用商店分发：Apple + Google 双头垄断

移动端 App 的可达性由两家控制：Apple App Store（iOS 唯一合法分发渠道，CR1=100% 对 iOS）、Google Play（Android 主渠道，但 Android 允许侧载，非唯一）。对 iOS，Apple 是绝对单点，一个 App 被下架，iPhone 用户无法安装，无侧载合法路径。

### 5. 上游依赖（子节点）

ir-cloud 自己绕不开的：

- ir-dns（DNS + CA）：托管在云上的服务仍需域名解析和有效证书才能被访问。ir-cloud 和 ir-dns 是"托管，命名"的配套，一个平台被下线常是两者同时被撤。
- ir-cables + ir-bgp（物理传输 + IP 路由）：云控制面的所有流量最终走光缆和 BGP 路由，是物理前提。
- ac-gpu / 通用服务器芯片：数据中心的算力硬件，但对 ir-cloud（可达性而非算力）而言，普通 CPU 服务器即可，不构成 GPU 那样的管制单点。
- en-crude / en-lng / ac-power（能源）：数据中心和边缘节点耗电，电力是运营成本项。
- fi-usd（美元结算）：云控制面服务以美元计价，需美元清算完成付款，切断支付是下线一个平台的常见配套动作（维基解密案）。

子节点候选（在"发现的子节点"登记）：
- ir-cloud-cdn / DDoS 缓解层（Cloudflare 近独占）：反向代理层的集中度和"撤保护即下线"机制值得独立拆，它是四个接口里唯一"以不作为完成拒绝"的，且射程最广。〔已定夺 2026-07-26：并入主表节点 `nodes/ir-cdn.md`，本表原建议的合并方向（以子节点吸收 ir-cdn）未采纳，为保持主表 79 节点口径不动；分工是本节点管平台下线方向，ir-cdn 管主权从外部拒绝 CDN 方向（俄罗斯限流案）。〕
- ir-cloud-appstore（Apple/Google 应用商店）：移动端可达性的双头垄断，对 iOS 是绝对单点，是"平台下线"里最少被计入 ir 栈的一层，值得独立拆。

### 6. 下游依赖方

- 中小网站和媒体（致命依赖）：绝大多数商业网站、新闻媒体、论坛无力自建全球托管+CDN+抗 DDoS，完全依赖这叠控制面。被撤=下线。依赖强度：致命。
- 移动应用（对 iOS 致命）：任何面向 iPhone 用户的服务，App Store 是唯一合法分发渠道，下架=iOS 用户无法安装。依赖强度：致命（iOS）/ 高（Android，可侧载但触达大降）。
- 大型平台（高依赖，有部分自建能力）：Meta、Netflix、字节跳动等有自建 CDN 和多云能力，对单一提供商的依赖低于中小站点，但仍受应用商店分发约束。
- 有敌人的争议站点（对 DDoS 缓解致命）：任何会招致 DDoS 攻击的站点（争议论坛、被政治targeting的媒体、加密货币服务）离不开 DDoS 缓解层，撤保护即被第三方攻击打下线。这是 Cloudflare 撤保护动作的直接受害群体。
- 库存缓冲：几乎没有。账户封禁即时生效；DNS 缓存 TTL（几分钟到几小时）给托管迁移一点点窗口，但 DDoS 攻击在盾牌撤走后几小时内就能压垮源站。

### 7. 替代路径 + fallback 等级

托管层替代：

在三家 Hyperscaler 之间迁移，或转向次级云（Oracle、DigitalOcean、Hetzner 等）、或自建机房。按五问：
- 替代哪一层：服务器托管；
- 多久接上：迁移一套生产环境从天到周计（数据、配置、依赖迁移）；
- 卡在哪：迁移期间服务中断或降级，且如果目标是被制裁实体，次级云和自建同样受美国法律约束（OFAC 制裁的实体，境外云也可能拒绝服务）；
- 谁有权限启动：服务运营者自己；
- 执行能力：技术上真实存在。
结论：对普通商业争议（ToS 违规）`partial`，可迁移但有中断和成本；对被制裁实体 `blocked`（合法路径上，替代云同样受约束）。

CDN + DDoS 缓解层替代：

从 Cloudflare 迁到 Akamai/Fastly/AWS Shield 等。按五问：技术上可迁移，但被 Cloudflare 主动撤保护的站点，往往是因为内容争议（Daily Stormer、8chan、Kiwi Farms），下一家 CDN/DDoS 提供商多半以同样理由拒绝接收（Kiwi Farms 案中，DDoS-Guard 等替代方也相继撤出）。所以对普通站点 `operational`（Cloudflare 只是众多 CDN 之一，可换），对"被行业共同拒绝"的争议站点 `blocked`，不是没有技术替代，是所有主流提供商在内容治理上趋同，形成事实上的行业封锁。

应用商店分发替代：

- iOS：`blocked`。App Store 是唯一合法渠道，无侧载。欧盟《数字市场法》（DMA）2024 起强制 Apple 在欧盟境内开放侧载，但仅限欧盟，且实施细节仍在博弈中（C3）。
- Android：`partial`。可通过 APK 侧载或第三方商店分发，但失去 Play 的触达和更新推送，用户装机意愿大降。

### 8. 重建壁垒 + 前置期

- 托管：建立全球竞争性 IaaS 需要百亿美元量级多年资本支出（同 ac-cloud），中小玩家做不到，但"够用"的替代托管（区域性云、自建机房）门槛不高，重建期月级，这使托管层不是最硬的单点。
- CDN + DDoS 缓解：建立全球边缘节点网络+抗 DDoS 能力需要大规模网络基础设施投入和多年运营积累，Cloudflare 的护城河是网络规模效应（节点越多、吸收攻击能力越强）。但技术替代存在（Akamai/Fastly），重建期年级。真正的壁垒不是技术，是行业内容治理趋同，这是社会性壁垒，不是技术壁垒，见第 7 维。
- 应用商店：对 iOS，重建等于重建一个和 iOS 竞争的移动操作系统生态，前置期十年级、事实上不可能。这是四个接口里最硬的单点。

### 9. 议价 / 控制机制

- 卡点 type：`permission`（账户/托管/分发许可）+ 对 DDoS 缓解层是 `service`（撤走一项持续服务）。全部通过账户状态和服务条款实现，不依赖物理截断，调用 permission-chokepoint 概念卡：节点还在运行，但托管/分发/防护通道被行政或合同手段锁死。
- 卡点 mode（分接口）：
  - 托管：平时 `open by default`；ToS 违规或制裁触发 `selective-seizure`（针对具体客户终止）
  - CDN/DDoS 缓解：平时 `open by default`；对争议站点 `selective-seizure`（撤走单个站点的防护）；行业趋同时对某类内容 `near-closure`（所有主流提供商拒收）
  - 应用商店（iOS）：`toll gate`（30%/15% 抽成的常态收费）+ 对下架目标 `selective-seizure`；结构上是 `closed`（唯一合法渠道）
- 控制机制核心：这叠接口把"内容治理"从一个言论问题变成一个基础设施问题。一个平台是否能在互联网上存在，实际上由几家美国公司的 ToS 执行部门和合规团队决定，不需要法院判决（虽然 OFAC 制裁会强制执行），平台可以依自己的服务条款单方面终止。这是 refusal-right-sources 里"所有权"来源的典型：Cloudflare/AWS/Apple 凭的是对自己服务这个环节的所有权，行使"我的条件即不服务你"。

### 10. 历史变迁（卡点怎么移动）

- 2010-12：维基解密公布外交电报后，Amazon（AWS）以 ToS 违规为由终止其托管，EveryDNS 停止域名解析，PayPal/Visa/Mastercard/Bank of America 切断捐款通道，这是"多接口同步下线一个平台"的第一次大规模公开案例，且是在无任何法院命令下、由私营公司依 ToS 完成（C4，广泛记录）。这个案例定义了 ir-cloud 的机制模板：国家施压（美国政界公开点名）→ 私营运营者依 ToS 执行（refusal-right-sources 里"国家施压、运营者执行"的组合，落地点在所有权、发起点在主权，不经法律文件）。
- 2017-08：Cloudflare 撤销对新纳粹网站 Daily Stormer 的服务，CEO Matthew Prince 公开表态"我今早醒来决定把一个人从互联网上删掉，这个权力不该存在"（C4），首次公开承认 CDN/DDoS 缓解层的"删除一个站点"权力，并对这个权力本身表达不安。这是 DDoS 缓解层作为可达性卡点的自我暴露时刻。
- 2019-08：Cloudflare 撤销对 8chan 的服务（El Paso 枪击案凶手在该论坛发布宣言后），8chan 被打下线数周，几经辗转（迁至 DDoS-Guard 等）才以 8kun 重新上线（C4）。
- 2021-01：Parler 三重打击。1 月 8–9 日 Apple App Store 和 Google Play 相继下架 Parler App，1 月 10 日 AWS 依 ToS 终止托管，Parler 约 36 小时后完全下线（C4，双方法律文件），这是"应用分发+托管"两层同步动作的最清晰案例，一个千万级用户平台在 48 小时内从主流互联网消失。Parler 起诉 AWS 反垄断，败诉。
- 2022-09：Cloudflare 撤销对 Kiwi Farms 的服务（详见"最近一次被争夺的事件"）。
- 2024：欧盟 DMA 生效，强制 Apple 在欧盟境内开放 iOS 侧载和第三方应用商店，这是应用分发单点第一次被主权监管撬开一道口子，但仅限欧盟，Apple 以各种合规设计限制其实际效果（C3）。

卡点移动的方向：从"隐性的技术服务"逐步变成"公开的内容治理权力"，每一次撤服务事件都把这叠接口的政治属性往台面上推一步；同时，欧盟 DMA 开始从监管侧反向撬动其中最硬的应用分发单点。

### 11. 因果层

主要锚在 real force，物质约束为辅。

- real force 层（高比重）：这叠接口的卡点根本来自被普遍采用，AWS/Cloudflare/App Store 的力量不是物理资源稀缺，而是海量服务和用户已经绑定在它们的控制面上，迁移代价（技术+触达）真实存在。这和 ir-dns 的 trust store、CUDA 的生态绑定同类。尤其 CDN/DDoS 缓解层的行业内容治理趋同，是一种纯社会性的 real force：技术上有替代，但所有主流提供商在"接不接这个客户"上趋于一致，形成事实封锁，这个封锁力量完全不在物质层。
- 物质约束层（辅）：全球 CDN 边缘网络和抗 DDoS 能力有规模壁垒（节点越多越强），应用分发对 iOS 是操作系统生态的物质垄断。这部分是真壁垒，但不解释"撤服务"这个动作本身，动作靠的是所有权+ToS，不是物质稀缺。
- 调用技巧层（低比重，但精准）：和 ir-dns 一样，撤服务是可以精确到单个客户的技术操作，粒度细、副作用小、门槛低，这使干预实际发生的频率高于物理卡点（每年都有撤服务事件）。

## 量化层

> 口径说明：ir-cloud 关注的是"可达性控制面"这个切面，不是整个云计算市场（那与 ac-cloud 重复计价）。Q1 只取 CDN/DDoS 缓解和应用分发这两个 ir-cloud 独有接口的市场规模；托管层的规模在 ac-cloud 已计，此处不重复。

### Q1. 市场规模

- CDN 市场：全球约 $200–250 亿/年（2023，C2，Grand View Research / Mordor Intelligence 商业报告口径，需原文核）。
- DDoS 防护市场：全球约 $40–50 亿/年（2023，C2，MarketsandMarkets 口径，需原文核）。
- 应用商店抽成收入：Apple App Store + Google Play 合计开发者付给平台的抽成，量级约 $300–400 亿/年（2023，C2，Sensor Tower / data.ai 口径推算；Apple Services FY2024 约 $960 亿含 App Store 但未单独披露 App Store 抽成）。
- 托管层规模见 ac-cloud（全球 IaaS 约 $1400 亿/年，2023，Synergy），此处不重复计入 ir-cloud。

【缺口：需要 Cloudflare 10-K（FY2024 营收/净利/市值）、Akamai 10-K、Grand View/Mordor CDN 市场报告原文、MarketsandMarkets DDoS 防护市场报告、Apple/Alphabet 应用商店抽成细分，投典藏工单。】

### Q2. 集中度量化

- 托管（IaaS）：CR3（AWS+Azure+GCP）约 60–65%（C3，Synergy Research 2024）。
- CDN + DDoS 缓解：Cloudflare 在"使用反向代理的网站"中约 80%（C3，W3Techs，口径限定，非全体网站）；企业级高端市场 Akamai/Fastly 份额更高，Cloudflare 主导的是长尾中小站点。price maker：Cloudflare（免费入口层压低了整个 CDN/DDoS 缓解市场的定价）。
- 应用分发：iOS CR1=100%（Apple，C4）；Android 主渠道 Play，但允许侧载，非绝对单点（C4）。

### Q3. 关键玩家财务概况

- Cloudflare（NYSE: NET）：FY2023 营收约 $13 亿（C3，需 10-K 核，FY2024 约 $16 亿量级）；长期以扩张换增长，接近盈亏平衡/微利；市值约 $300–400 亿区间（C3，2024，波动大需核）。资本纵深：中等，它的护城河是网络规模而非利润积累，扛政治压力的能力靠"删一个客户几乎无财务损失"而非靠现金储备。
- Akamai（NASDAQ: AKAM）：FY2023 营收约 $38 亿（C3，需 10-K 核），成熟盈利企业，毛利率高。
- Fastly（NYSE: FSLY）：FY2023 营收约 $5 亿（C3），规模小、盈利弱。
- AWS/Azure/GCP：见 ac-cloud（AWS FY2024 云营收 $107.6B C4 等）。
- Apple：Services 分部 FY2024 约 $960 亿（C3-C4，含 App Store，但 App Store 单独抽成未披露）。

这组数字说明一个关键点：撤服务对提供商几乎无财务代价（一个争议客户占其营收微不足道），所以"扛政治压力反制"的激励极弱，和 ir-dns 里 trust store 控制者"不从中盈利"是同构的财务异常：最核心的下线权力，握在删掉一个客户几乎不痛的主体手里。

### Q4. 下游依赖度量化

- 本节点对下游：对中小网站，托管+CDN+DDoS 缓解占其 IT 成本的相当比例（C2，无精确统计），但对可达性是 100% 依赖，没有它服务不存在。
- 下游对本节点：被撤服务后，普通站点迁移新提供商从数小时（换 CDN）到数天（迁托管），但争议站点因行业趋同可能永久无法接入主流控制面；iOS App 被下架则无合法替代路径。库存缓冲：几乎为零。

### Q5. 断供 / 管制的经济冲击量级

单个平台被下线的冲击：Parler（约 1500 万注册用户）48 小时内从主流互联网消失，直接经济价值损失难以精确量化，但平台估值归零级（C2）。系统级冲击（假设一家 Hyperscaler 或 Cloudflare 大规模故障）：2021-06 Fastly 一次配置错误导致全球大量主流网站（含 Amazon、Reddit、纽约时报、英国政府网站）同时下线约 1 小时（C4，广泛报道），说明单个 CDN 提供商的故障即可造成全球可达性的分钟级大面积中断，经济损失量级以亿美元计（C2 推算）。

【缺口：需要 Fastly 2021-06-08 事故技术复盘报告、Cloudflare/Akamai 重大故障的第三方经济损失评估。】

### Q6. 资本流向与利润归宿

- 托管层：利润沉淀在三家 Hyperscaler（规模经济，见 ac-cloud）。
- CDN/DDoS 缓解层：利润在企业级高端市场（Akamai/Fastly 的大客户合同）沉淀，长尾中小市场因 Cloudflare 免费入口层利润接近零，和 ir-dns 里 Let's Encrypt 压平证书利润同构。
- 应用分发层：利润高度沉淀在 Apple 和 Google（30%/15% 抽成是纯平台租金，边际成本极低），这是四个接口里利润最厚的一层，也是欧盟 DMA 反垄断的直接靶心。
- 政治含义：下线权力和利润归宿在这个节点上错位，最厚利润在应用分发（Apple/Google），但最频繁被行使的下线动作在 CDN/DDoS 缓解层（Cloudflare，几乎无财务利益）。政治压力首先打到谁的资产负债表上，取决于打的是哪个接口。

## 方向、两条流、最近一次被争夺的事件

### 拒绝方与操作方

拒绝方：分两类来源，常组合出现，
- 平台自身（所有权来源）：AWS/Cloudflare/Apple 依自己的服务条款单方面终止服务。凭的是对自己服务环节的所有权（refusal-right-sources"所有权"来源）。这是 ir-cloud 最常见的拒绝方，不需要法院命令。
- 国家施压 → 平台执行（主权发起、所有权落地）：OFAC 制裁一个实体，平台被强制拒绝服务；或政界公开点名施压（维基解密案），平台"自愿"依 ToS 终止。发起点在主权，落地点在所有权，可不经法律文件，这正是 refusal-right-sources 里"国家施压、运营者执行"的组合形态。

操作方：云控制面的工程师和合规团队。和 ac-cloud 一样，这里的操作方力量来自 ToS 的合同权力（由平台单方行使），不来自劳动者集体行动，云服务不像煤矿那样依赖大量可集体行动的体力工人，个别工程师抗议不构成系统性操作方力量。operating-layer 概念卡在这里不适用（提供者是平台的合同权力，不是操作层意义上的一批工人）。

一个 refusal-right-sources 没直接覆盖的机制变体：DDoS 缓解层的下线不是控制方"主动切断"，而是控制方"停止提供防护"（不作为），实际打击由第三方的 DDoS 攻击完成。控制方的拒绝动作是"撤走盾牌"，打击者是别人。这既不是标准的"拒绝方主动切断"，也不是"操作方扣住配合"，而是第三种：以停止防护、放任第三方攻击来完成下线。这个"以不作为完成拒绝"的机制，现有 refusal-right-sources 和 permission-chokepoint 都没有单独一格。（此处疑似缺口，本轮不建卡，留给反思层判断是否值得单立或并入 refusal-right-sources。）

### 两条流

物理流（可达性中断点）：这个节点是 ir 栈里对物理流可达性影响最直接的可达性执行面。托管账户封禁、CDN 撤走、DDoS 盾牌撤走，都直接让内容送不到用户面前，这是纯粹的可达性中断，比 ir-dns（命名/信任）更靠近"内容能不能被取到"这一端。

价值流（价值中断点）：应用分发层的 30%/15% 抽成是价值流上的收费闸（toll gate），Apple/Google 对经过其商店的每一笔交易抽成。这一层同时是可达性卡点和价值卡点。

ir-cloud 因此是同时压在两条流上的节点：托管/CDN/DDoS 缓解主要压物理流（可达性），应用分发同时压物理流和价值流（可达性+抽成）。

### 最近一次被争夺的事件

Cloudflare 撤销对 Kiwi Farms 的服务（2022-09-03），ir-cloud 的 DDoS 缓解接口迄今最清晰的一次被争夺，因为它专门照出这个平时最隐形的接口。

用五个阅读动作来读：

① 校准颗粒度：这场争夺不是在争"Cloudflare 该不该存在"这个宽泛问题，而是在争一个非常具体的点：Cloudflare 作为一个自称"中立的、不做内容判断的基础设施提供商"，在持续的公众压力下，是否会撤走对一个特定站点的 DDoS 防护，把它从"我们不当内容警察"的立场上逼下来。争夺的靶点是 Cloudflare 反复申明的"基础设施中立"承诺，正如 ir-dns 里争夺的靶点是 ICANN 的"技术中立"承诺，两者是同一类"靠自我设定的中立承诺锁住、而非靠物理不可能锁住"的卡点。

② 反应链：Kiwi Farms（一个以骚扰、起底特定个人著称的论坛）针对一名跨性别活动人士的骚扰升级 → 该活动人士发起 #DropKiwiFarms 公众运动、持续施压 Cloudflare（2022-08）→ Cloudflare 8 月底发博客坚持"不做内容审查、撤服务是危险先例" → 公众压力和媒体报道进一步升级 → Cloudflare 9-03 反转，撤销对 Kiwi Farms 的服务，CEO 承认这是"一个我们不愿开的先例，但眼下的威胁是紧迫的" → Kiwi Farms 转向 DDoS-Guard 等替代提供商，但这些替代方也相继撤出，站点几经下线/上线。

反应链暴露的结构：拒绝方（Cloudflare）在面对持续公众运动时，"基础设施中立"承诺的稳定性远不如它口头宣称的那样硬。撤服务的决定不是来自法院、不是来自政府，而是来自一场持续的社会运动，这是 ir-cloud 和 ir-dns 的区别之一：ICANN 面对的是主权国家的战争请求（俄乌），Cloudflare 面对的是自下而上的公众运动，两种压力来源不同，但都作用在"中立承诺"这个同一类地面上。

③ 被当成舞台的一方：Cloudflare 自己。主流叙述是"活动人士 vs Kiwi Farms"，Cloudflare 被叙述成中立的基础设施背景。但真正做出决定性动作的是 Cloudflare，它撤不撤保护，直接决定这个站点能不能在互联网上存在。它不是舞台，是持有开关的一方。把它从"中立背景"里点出来，就看清了 DDoS 缓解层是一个真实的可达性卡点，而不是一个被动的技术管道。

④ 时间维度：Cloudflare 从 8 月底公开坚持"不撤服务、这是危险先例"到 9-03 反转撤服务，只隔几天。这个快速反转本身是动作，它证明"基础设施中立"承诺在足够强的公众压力下的实际强度以天计，不以原则计。对比 ir-dns 里 ICANN 面对俄乌战争压力时守住了"无权撤销"的立场（措辞是"我无权"而非"我有权但克制"），Cloudflare 的措辞是"我有权但这次不得不用"，两种措辞对未来的约束力完全不同：ICANN 把自己固定在"无权"，Cloudflare 承认"有权"，后者一旦承认，这个卡点的政治性质就变了，此后每一次公众运动都可以要求它再用一次这个它已承认拥有的权力。

⑤ 把数字和说法当动作：Cloudflare 8 月那篇"我们不撤服务"的博客本身是一个动作，它试图把"基础设施中立"重新确立为不可撤销的地面，好让自己免于每一次内容争议的施压。这个动作失败了（几天后就反转），失败本身照出：一个私营公司单方面宣布的"中立"，在持续公众压力下守不住，因为它没有 ICANN 那种多利益相关方治理结构和"无权"措辞的保护。

结论：这场争夺照出 ir-cloud 的核心结构，下线权力在少数美国私营平台手里，凭的是对自己服务的所有权（refusal-right-sources），但这个权力的行使门槛不是法律、而是社会压力和平台自身的内容治理立场；平台反复申明的"中立"承诺，在足够强的压力下以天级失守。DDoS 缓解层尤其危险，因为它的下线机制是"撤走防护、放任第三方攻击完成打击"，控制方本身不必动手，射程却覆盖所有挂在它后面的海量站点。这个卡点的政治性质，取决于平台把自己钉在"无权"还是"有权但克制"，Cloudflare 已经承认了后者。

## 政治传动层

### A. 公开接口

- 各平台 Terms of Service / Acceptable Use Policy：AWS Acceptable Use Policy、Cloudflare Terms of Service、Apple App Store Review Guidelines、Google Play Developer Policy，均为公开文件（C4），规定平台可单方面终止服务的条件。这是 ir-cloud 最主要的控制接口，不是法律而是合同。
- OFAC 制裁条例（31 CFR）：被制裁实体，美国平台被强制拒绝服务，是 ToS 之上的法律强制层。
- 欧盟《数字市场法》（DMA，Regulation 2022/1925）：2024 起强制守门人平台（含 Apple/Google 应用商店）开放，是从监管侧反向撬动应用分发单点的接口（C4）。
- 欧盟《数字服务法》（DSA）：对超大型平台的内容治理义务，影响平台撤服务的合规逻辑（C3）。

### B. 控制状态流转

对普通商业客户：`allow by default`（默认服务）→ ToS 违规或制裁触发 `selective-seizure`（针对性终止）。翻转门槛：平台合规部门单方面决定（无需外部批准），或 OFAC 制裁强制。

对争议内容站点：`allow by default` → 公众运动/媒体压力升级 → `selective-seizure`（单站撤服务）→ 行业趋同时 `near-closure`（所有主流提供商拒收）。翻转门槛：社会压力达到平台内容治理立场的临界点，已被证明以天级可翻（Kiwi Farms）。

对 iOS 应用分发：结构性 `closed`（唯一合法渠道）+ 对下架目标 `selective-seizure`。DMA 在欧盟境内撬开 `partial open`，但仅限欧盟。

### C. 适用账本

- 服务合同账：ToS 是核心账本，记录平台与客户的服务关系和终止条件。
- 合规账：平台内部对制裁名单、内容违规的合规审查记录。
- 抽成账（应用分发）：App Store/Play 对每笔交易的 30%/15% 抽成，是价值流的收费时点账。

### D. First Payer

被撤服务的平台运营者首先付代价（服务下线、用户流失、平台估值归零）；次一步是该平台的用户（服务不可达）；对被制裁实体，first payer 是实体自身。应用分发下架的 first payer 是 App 开发者（失去 iOS 触达）。

### E. 时点

- 账户封禁/ToS 终止：平台决定即时生效，服务下线以小时到天计（Parler 约 36 小时）。
- DDoS 盾牌撤走：撤走后第三方攻击在数小时内压垮源站。
- 应用下架：平台决定即时，用户端存量 App 可继续用但无更新，新用户无法安装。
- DMA 应用分发开放：2024 分阶段生效（欧盟境内）。

### F. 叙事合法化

- 平台主动撤服务：靠"内容治理""社区安全""不为仇恨/暴力/骚扰提供便利"叙事合法化，动员公众舆论和媒体。Kiwi Farms 案的叙事是"防止对特定个人的骚扰升级为现实伤害"。
- 国家强制（制裁）：靠"国家安全""制裁合规"叙事，无需舆论动员，法律强制。
- 反向叙事（批评撤服务）：靠"言论自由""基础设施不该做内容警察""少数私营公司不该掌握谁能上网的权力"，Cloudflare CEO 2017 年"这个权力不该存在"的表态就是这一叙事的自我表达。这个反向叙事是 ir-cloud 卡点使用的主要抑制因素，但已被证明抑制力以天级失效。

## 卡点分析

### 卡点 1：CDN + DDoS 缓解层（Cloudflare 近独占）

- 位置：ir 栈 L1，内容分发与抗攻击防护层
- 持有者：Cloudflare（美国）为主，Akamai/Fastly/CloudFront 次之
- 卡点来源：网络规模效应（real force）+ 行业内容治理趋同（社会性 real force）+ "撤保护即下线"的低成本精准机制 + 已有多次实施案例（Daily Stormer/8chan/Kiwi Farms）
- 政治进入后转移：撤服务不转移持有者，是持有者依所有权行使拒绝；行业趋同使替代提供商也拒收，形成事实封锁
- 干预窗口：常开，每次内容争议+公众运动都可触发，门槛是社会压力而非法律
- 最硬反例 + 过三关：反例「Cloudflare 只是众多 CDN 之一，站点可以换提供商，不是真卡点」。
  - 前提成不成立：对普通站点成立（有 Akamai/Fastly 等替代）；对被行业共同拒绝的争议站点不成立（替代方相继撤出，Kiwi Farms 实证）。
  - 可不可比：普通站点和争议站点面对的是不同的市场，普通站点面对的是竞争市场（可换），争议站点面对的是内容治理趋同后的事实封锁（换不掉）。两者不可混为一谈。
  - 真发生过：Kiwi Farms 被 Cloudflare 撤服务后，DDoS-Guard 等替代方也相继撤出，站点几经下线，事实封锁真实发生过。
  - 结论：对普通站点，CDN/DDoS 缓解不是硬卡点；对被行业共同拒绝的站点，它是硬卡点，且下线机制是"撤保护、放任第三方攻击"这个最隐形的一种。反例只对普通站点成立，不推翻争议站点的卡点判断。

### 卡点 2：应用分发（Apple App Store 对 iOS）

- 位置：ir 栈 L1，移动端内容可达性层
- 持有者：Apple（iOS 唯一合法渠道，CR1=100%）
- 卡点来源：操作系统生态的物质垄断（iOS 唯一分发渠道）+ 无侧载 + 30% 抽成的规模经济
- 政治进入后转移：DMA 在欧盟境内强制开放侧载，是主权监管第一次撬动这个单点，但仅限欧盟且 Apple 以合规设计限制其效果
- 干预窗口：对下架目标常开（Apple 单方面决定）；对结构性开放，DMA 在欧盟境内撬开一道口子
- 最硬反例 + 过三关：反例「Android 允许侧载，移动分发不是单点」。
  - 前提成不成立：对 Android 成立（可侧载）；对 iOS 不成立（无合法侧载）。
  - 可不可比：iOS 和 Android 是两个不同的生态，iOS 用户无法通过 Android 侧载获得 App，对一个只想触达 iPhone 用户的服务，Android 的侧载能力不解决问题。
  - 真发生过：Parler、Fortnite（Epic v. Apple）都实证了 App Store 下架对 iOS 触达的致命性。
  - 结论：对 iOS，应用分发是硬单点，反例（Android 可侧载）不适用于 iOS 生态。

## 级联关系

- 上游来自：ir-dns（域名解析+证书是可达前提）；ir-cables + ir-bgp（物理传输+路由）；ac-power/en（数据中心电力）；fi-usd（美元计费）
- 下游影响：应用层互联网全体（网站、媒体、论坛、移动 App）；一个平台的可达性存亡；被制裁实体的在线存在
- 跨栈耦合：
  - 接 ps-sanctions（OFAC 制裁实体切断托管/分发是 ir-cloud 执行的一种形式），`许可+合规`
  - 接 ir-dns（下线一个平台常是托管+DNS 同时撤，维基解密案），`可达性级联`
  - 接 fi-card / fi-stablecoin（切断支付是下线平台的配套动作，维基解密案），`价值流级联`
  - 接 ir-filter（方向相反：ir-filter 是主权在境内过滤入境流量，ir-cloud 是全球控制面从源头下线），`可达性，反向`
- 跨域效应：影响法玛（AI STS：平台内容治理权力集中在少数美国公司，是"谁能在互联网上发声"的基础设施表达）；影响墨衡（AIgora 共和国：私营基础设施对言论可达性的单方面决定权，是宪制层面"表达自由的基础设施前提"问题）
